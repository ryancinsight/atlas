`ADD-COMPLEX-GRAD` has an explicit decoder. An input `native_tensor` has dtype `complex64`, device `cpu`, shape `[]`, one tagged complex scalar in `values`, and `requires_grad=true`. `values` is a serialized one-value container; it is never passed as a list to a tensor constructor. The future native harness extracts its sole `{kind:"complex",real,imag}` value, constructs the Python scalar with `complex(real, imag)`, then constructs a rank-zero tensor as `torch.tensor(value, dtype=torch.complex64, device="cpu", requires_grad=True)`. In contrast, `alpha` is a `python_number` with `python_type="complex"`; it decodes directly to a Python complex Number and receives no tensor/list conversion. The native operation is `torch.add(a, b, alpha=alpha)`.

The real scalar loss is `result.real.sum()`, with dtype `float32` and shape `[]`. Its tagged real cotangent decodes to a rank-zero float32 tensor supplied as the backward gradient. Results and both VJPs retain explicit `native_tensor`/`complex64`/shape-`[]` records and tagged complex scalar values; the loss uses a `float32` rank-zero tensor with a tagged real value. For real cotangent `s`, the exact analytical formulas are `z=a+alpha*b`, `loss=Re(z)`, `grad_a=s`, and `grad_b=s*conj(alpha)`. The baseline values are `a=1+2i`, `b=3-i`, `alpha=2+i`, `s=1`, giving `z=8+3i`, loss `8`, and VJPs `1+0i` and `2-i`.

The stdlib-only oracle decodes the inputs, computes with exact rational real/imaginary components, and requires every declared component, product and sum to be exactly representable in binary32.
