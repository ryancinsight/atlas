## ATLAS-COEUS-REDUCTION-ORACLE-005 — The Metal reduction test's oracle rejects the ops it is meant to verify [patch] — todo
- outcome: `crates/coeus-metal/tests/reduction.rs` builds each expected value with the entry point that admits its op, so all five reductions and the four scans are actually compared against leto instead of the test aborting at the second op.
- basis 2026-10-05 (coeus `main` at `88c65717`, and the failing run's own log): the test loops `for (op, expected) in [(Sum, …), (Prod, …), (Mean, …), (Min, …), (Max, …)]` at `crates/coeus-metal/tests/reduction.rs:32` and, inside the loop, produces the oracle with `coeus_leto::reduce_into(op, &layout, &input, 1, &Layout::new([2, 1].into()), &mut expected_values).expect("Leto reduction oracle failed")` (`:40`, `:48`). That entry point is `pub fn reduce_into<T: LetoScalar>` (`crates/coeus-leto/src/dispatch/reductions.rs:114`) and it **rejects `Mean` and `Prod` by design** at `:122`, returning `LetoError::StorageError` with "requires a FloatElement sample; call reduce_mean_into or reduce_prod_into instead" (`:125`). The bounded entry points are `reduce_mean_into` (`:143`) and `reduce_prod_into` (`:154`), both `T: LetoScalar + FloatElement`. The doc comment at `:109-113` states the intent: routing them here "would force every caller … to carry that bound".
- observed: run 37280610978, job `Metal Coeus provider contracts`, 2026-10-05T08:02. The test panics at the oracle — `reduction.rs:48:10`, reason exactly the message above — so the Metal comparison never runs for `Prod`, and because the panic is inside the loop the test ends there. `Sum` is the only reduction compared, and everything after it never executes: the `Mean`, `Min` and `Max` comparisons, and the four scan oracles (`cumsum_into` `:68`, `suffix_sum_into` `:79`, `cumprod_into` `:96`, `suffix_prod_into` `:113`), which do use bounded entry points and would have passed. The job summary reads "7 tests run: 6 passed, 1 failed, 2 skipped", which hides that nine of this test's ten comparisons have no coverage.
- method: dispatch on `op` in the oracle — `reduce_mean_into` for `Mean`, `reduce_prod_into` for `Prod`, `reduce_into` otherwise. The Metal side already takes a `ReductionOp`, so only the oracle call changes.
- priority: verification; needs: none.
- acceptance: the test passes with all five reductions and four scans compared, and mutating the Metal `Prod` or `Mean` path fails it.
