## ATLAS-IDENTITY-NARROW-ADDED-DEPS — Narrow the source-identity clean when a run adds dependencies [arch] — todo
- **outcome:** a gate whose manifest change adds dependencies cleans and holds exclusive only the packages whose artifact variant actually moves, so peers sharing the rest of the closure keep their artifacts and their shared leases.
- **evidence (2026-10-01, basis `4cbd966b6`):** a ritk-codecs gate adding `coeus-core` and `eunomia` grew its closure from 6 to 35 packages, cleaned all 35 and held them exclusive through `cargo clean` (over 5 min) and its clippy command; a metis push and an athena push each failed after the 900 s lease wait behind it.
- **falsified approach (ryancinsight/atlas#418, closed):** narrowing on `cargo metadata` records and per-package edges is unsound. A judge reproduced three real-Cargo cases in which a narrowed run records a variant the build no longer uses: `features` merge dev-dependency and cross-member activation, a version bump changes a package id so a known package reads as new, and an edition change moves the implicit resolver.
- **proposed witness:** build the record from Cargo's own `--message-format=json` `compiler-artifact` messages (per-unit `features`, `filenames`, `fresh`) instead of filesystem discovery; a dependency whose source identity is unchanged then never needs cleaning, since its variant names come from the build itself.
- **acceptance:** #418's `DependencyAdditionTestCase` cleans `[p]` and `[p, v]`; the judge's three counterexamples (dev-dependency features, version bump, edition 2018 -> 2021) record the variant Cargo built; the feature and root-profile counterexamples keep passing.
- **priority:** tightening
- **scope:** `scripts/atlas_build_identity.py`, `scripts/atlas_build_artifacts.py`, `scripts/tests/test_atlas_build_identity.py`, `docs/adr/0064-shared-build-source-identity.md`
- **spike result (2026-10-01, cargo 1.97):** `cargo clippy --all-targets --message-format=json`, `cargo doc --no-deps --message-format=json` and `cargo nextest run --cargo-message-format json` each report a `compiler-artifact` per unit, fresh units included, with `filenames` and the activated `features`; activation differs per command (a dev-dependency feature appears under clippy and nextest, not under doc), which is the first counterexample's mechanism.
- **next:** revise ADR 0064 so a run records each package's files from its command's `compiler-artifact` messages and cleans only packages whose source identity changed; then implement against the acceptance above.
