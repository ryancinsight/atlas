## ATLAS-TRUSTED-PUBLISHER-BOOTSTRAP-001 - Register trusted publishing for the token-first-published crates [patch] - todo
- Outcome: `eunomia-derive` 0.9.0 (2026-10-03) and `apollo-dctdst-core` 0.16.0 (2026-10-05) reached the index through one-shot API-token publishes, because crates.io cannot hold a trusted-publishing configuration for a crate that does not exist yet (the `crates-io` environment token in `ryancinsight/kwavers` is the only credential that minted them). Both crates' later versions are meant to ride `rust-lang/crates-io-auth-action` OIDC in the Atlas publish machinery, but their crates.io settings carry no trusted publisher yet: the next version bump of either crate fails its release at the token step.
- Owner: stack owner (crates.io account settings; not reachable from any repository). Scope: the trusted-publishing settings of the two crates only. Non-goals: the environment token and the one-shot publish mechanism, both delivered; any other first publication (each repeats the same bootstrap and files its own row here).
- Acceptance: each crate's crates.io trusted-publishing settings name its owning repository and release workflow (`eunomia-derive`: `ryancinsight/eunomia`, `rust-release.yml`; `apollo-dctdst-core`: `ryancinsight/apollo`, `rust-release.yml`), and the next version of each publishes through OIDC with no stored token.
- Verification: record the settings confirmation and the first OIDC-published version of each crate before closing. Until then a version bump of either crate failing at the token step is this item, not a pipeline regression.
