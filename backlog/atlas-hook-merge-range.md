## ATLAS-HOOK-MERGE-RANGE — A pushed branch update gates and budgets against the wrong base [patch] — todo
- Outcome: every branch update, with or without `git merge origin/<default>` in its range, measures the `atlas-artifact-budget.py --base` from the merge base with the fetched `origin/<default>`, so a board the branch shrinks against main is not refused for growing against the previous tip. An update whose range contains such a merge also measures the gate range from that merge base, so main's commits are not gated (a `Cargo.toml` change on main gates the whole workspace).
- Evidence (origin/main 12708acf3ae4892d4443627f0d6d5016ddeb29d7, `scripts/git-hooks/pre-push`): for a remote tip that is an ancestor of the local tip the base is the remote tip (lines 558-561), so the range `<remote sha>..<local sha>` includes every main commit the merge brought in. `base-triggers` over that range (lines 2057-2065) then prints "cast counts are compared with the pushed base (...)" for a main commit that changed `Cargo.toml`.
- Budget witness (kwavers `.githooks/pre-push` lines 558-561, the same lines as `scripts/git-hooks/pre-push`, whose `--base` is passed at lines 954-973; `evaluate` at `atlas-artifact-budget.py` line 280): the fix push of kwavers#1080 (`gap_audit.md` 4594 lines; 4560 at its previous tip; 4870 at main) was BLOCKED "4594 lines (3594 over budget) and grew from 4560" and passed on a new branch, kwavers#1081. leto#404's merge push gated main's own code (now leto#406).
