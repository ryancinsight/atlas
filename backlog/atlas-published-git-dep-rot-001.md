## ATLAS-PUBLISHED-GIT-DEP-ROT-001 — Published members carry floating git deps that rot every fresh resolution [arch] — todo

- priority: correctness
- outcome: a fresh resolution of any published member's tarball (and of any consumer's git edge onto a member's main) compiles coherently forever, because first-party requirements name registry versions, not floating git branches.
- evidence (basis 2026-10-05): apollo's pending-publish run 37275972653 fails at the plan's tarball verification through `apollo-fft -> apollo-leto-interop -> leto`: leto's fresh resolution hits `stencil.rs` E0599 (`in_unit` / `T: UnitScalar`) because leto's manifest deps are `git+version` (aequitas, eunomia, moirai, mnemosyne, themis) and float to upstream mains that are dev-ahead of the API leto's code expects. The same rot made the 0.43.1 registry baseline unbuildable (ATLAS-SEMVER-BASELINE-ROT, PR #489) — that class is now baked into published artifacts: leto 0.45.0's tarball carries the same floating manifest, so every downstream fresh resolution of it breaks the same way.
- mechanism: `git+version` first-party deps resolve the upstream default branch at build time; a published tarball or a consumer verification that resolves without the member's lockfile takes whatever in-flight state that branch holds. The stack's registry releases (eunomia 0.9, hermes-simd 0.8, moirai 0.7, mnemosyne 0.9, themis 0.11.1, melinoe 0.10, aequitas 0.2.1) already exist, so a registry requirement resolves the coherent published set instead of a moving branch.
- recommended option: members' manifests declare first-party deps as registry requirements (version-only); local development redirects them through the overlay (`[patch.crates-io]` sections — the generator gains that section form alongside the git-URL patches it already emits). Rejected: `rev =` pins (quarantine per pin discipline, and they orphan under rebase merges the same way the semver baselines did); rejected: verifying consumers' tarballs against the member's own lock (masks the rot the real consumer hits).
- scope: every member whose manifest carries `git+version` first-party deps (leto, apollo, gaia, athena, kwavers per their manifests); the overlay generator (`[patch.crates-io]` emission); one ADR recording the convention change.
- next: the wave's owners take the convention decision (ADR draft with the recommendation above); the migration is dependency-ordered per member — manifest edit + lock regeneration + the overlay generator, each member a green increment.
- acceptance: `cargo package`'s tarball verification passes fresh for every published member; apollo's pending pipeline (the current red) goes green; the semver gate's baseline probe no longer finds rotted baselines for post-migration releases.
