## ATLAS-ROOT-CONFORMANCE-MATERIALIZE-CRASH — The checker crashes materializing the root repo on Windows [correctness] — todo

- priority: correctness
- outcome: a push from the atlas root runs the conformance checker to completion on every host.
- evidence: after #501 lets a root push match its own stack, the gate's checker invocation crashes on Windows: `materialize_member` -> `link_snapshot` calls `content.mkdir(parents=True)` on `<scratch>/atlas` and the path already exists, so `FileExistsError [WinError 183]` aborts the member scan and the ratchet compares against garbage and blocks the push with a phantom raise (the board push of 2026-10-06 was blocked this way; the same args on the CI host pass). Root cause candidate: the root repo materializes twice or its member-path collides with the baseline materialization.
- next: land the `link_snapshot` fix, then push the board closure the gate refused.
- acceptance: the root push's checker run completes with real counts on Windows and Linux, and the phantom-raise block is gone.
- Fixed 2026-10-19 in the working tree: `link_snapshot` now takes a free directory per materialization (`<checkout>` and then `<checkout>-1`, `<checkout>-2`, …) instead of asserting the name is unused, so the root push's two snapshots of one checkout — the pushed content and the baseline config root — no longer collide on `FileExistsError [WinError 183]`. The member's identity moved with the snapshot: the fleet scan and `scan_member` pass the member name to `scan_repo` rather than reading it back from the snapshot path, which is what the sanctioned-root allowance was doing (`sanctioned_root_names` takes the member first, the directory basename only as a proxy). Reproduced on this Windows host: `atlas-conformance.py check --repo apollo --member-path D:/atlas --member-revision HEAD` raised `FileExistsError` at `<scratch>/atlas` before the fix and completes after it, with the fleet scan's counts unchanged. 182 conformance tests pass, including a new one that materializes one checkout twice into one scratch and holds each snapshot to its own revision.
