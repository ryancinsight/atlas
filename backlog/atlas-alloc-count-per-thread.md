## ATLAS-ALLOC-COUNT-PER-THREAD — Count test allocations on the measuring thread only [patch] — todo
- Outcome: every stack allocation-budget test counts allocations made by the thread under test, so libtest's own main-thread allocations never land in the measured window.
- Evidence: `stats_alloc` counts process-wide. ryancinsight/horae#80 traced a `left: 4, right: 0` failure to libtest's main thread allocating after spawning the test thread, and fixed horae alone. The same `Region::new` pattern is in asclepius `crates/asclepius/tests/allocation_instrument.rs`, harmonia `tests/allocation.rs` and `tests/field.rs`, hyperion `tests/contracts/layout_and_allocation.rs`, proteus `tests/layout.rs`, and athena `crates/athena-leto/tests/allocation.rs`. The same process-global shape is hand-rolled in `moirai-async/tests/task_poll_allocations.rs`: it installs a counting `#[global_allocator]` and asserts a 64-yield and a 1,024-yield run allocate identically, and on moirai `main` (run 37328252253, 2026-10-05) it read 4 and 8. No thread of moirai's is in that window: `AsyncExecutor::new` spawns nothing (`moirai-async/src/executor/core.rs:35-45`) and `block_on` polls on the calling thread (`:217-254`), while the process-global reactor thread (`moirai-pal/src/reactor/tls.rs:109-118`) starts only from `with_current`, which only `moirai-pal/src/net.rs:83` calls. The window is therefore the libtest harness thread — the same `left: 4, right: 0` signature as horae#80 — and the 1,024-yield window is simply open longer, so the assertion cannot separate a real per-poll allocation from the harness thread's.
- Flake: this assertion alone is moirai `main`'s red, and it is non-deterministic — runs 37249355480 and 37274209209 disagree on the same commit `5fae9ae70`, and the red tip `12f5353a` differs from the last green `main` by `a922ceb2`, three workflow YAMLs. `moirai-async/tests/wake_batch_allocations.rs` passes in the same run because it uses no executor and one synchronous call inside the window.
- Oracle: per member, a test that allocates on a second thread inside the window still reads zero for the measuring thread, and the existing budgets hold unchanged.
- Landed: the wrapper is `mnemosyne::counting` (`CountingAllocator::new(inner)` + `measure`, mnemosyne-memory 0.9.0, mnemosyne `bdaba5bf`). All seven named test files now use it: athena, harmonia (`tests/allocation.rs`, `tests/field.rs`), hyperion and proteus already in their trees; asclepius (`crates/asclepius/tests/allocation_instrument.rs`, `2cf1379` on local `main`) and moirai (`moirai-async/tests/task_poll_allocations.rs`, `7e66c68e` on `fix/moirai-main-diverged-2026-10-05`) landed 2026-10-06; horae moved off `allocation-counter` (`3c4f580` on local `main`, the dev-dependency dropped). moirai's budget keeps counting allocation and reallocation calls (`delta.allocations + delta.reallocations`), the calls the old counter counted, and its poll test passed five consecutive runs after the switch.
- priority: verification
- needs: none
- scope: mnemosyne (the wrapper), then the seven test files above and their manifests; horae moves off `allocation-counter` with them.
