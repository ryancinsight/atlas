## ATLAS-BOARD-INDEX-LADDER-CRASH — The board index and compact tools mishandle the milestone ladder [patch] — todo
- Outcome: `scripts/atlas-board-index.py` `check` and `generate` never end in a traceback: `backlog/milestones.md` is skipped as a ladder, and any other per-item file without a `## ` heading is reported as a `BoardIndexError` naming its path; `scripts/atlas-board-compact.py` neither counts nor deletes a ladder block of either slug form.
- Evidence (origin/main 12708acf3ae4892d4443627f0d6d5016ddeb29d7; `python scripts/atlas-board-index.py check <archive of the member's backlog.md and backlog/>`, exit 1): `item_fields_from_file` raises `ValueError: ... no '## ' heading found` (line 96), which `main` does not catch because it catches only `BoardIndexError`. Reproduced on mnemosyne e05b61001 (`backlog/milestones.md`), leto a1568745 (`backlog/leto-spmv-finite-range-20261020.md`, whose heading is `# `, then `backlog/milestones.md`) and the head of hermes#282 (closed).
- Same class in `scripts/atlas-board-compact.py` (prometheus#88, F9; read and probed at 6ee24b06a): it never imports `LADDER_HEADING`, which `atlas-board-lint.py` line 584 applies, so the result depends on the slug. A digit or capital slug that `ITEM_ID` (`scripts/atlas_board_items.py` line 36) also matches (`M-1.0`, read as the item `M-1`) is counted as an item: a probe of that block and one item prints `2 items`, and a real run keeps both. A word slug (`M-first-path`, the canonical `M-<slug>` form) is classed as a narrative section: `--dry-run` prints `1 items (0 would delete), 1 narrative sections`, and a real run deletes the block and its anchor (11 -> 6 lines) because `narrative_keep_reason` finds no open checkbox, open item id or open-work wording in it. The cause is the `ITEM_ID` count plus the narrative-section deletion, not `split_items`. Oracle: tests in `scripts/tests/test_atlas_board_compact.py`, one ladder block of each form, that neither is counted as an item or narrative section nor deleted, failing on origin/main.
- No atlas workflow or hook runs `check` (`git grep board-index -- .github scripts/git-hooks .githooks Makefile` is empty), so the crash shows only when a member runs it by hand.
- Oracle: tests in `scripts/tests/test_atlas_board_index.py`: a tree with a ladder file `backlog/milestones.md` (no `## `) checks and generates with exit 0 and no index line for it; a tree with a per-item file lacking `## ` exits 1 with that path on stderr and no traceback.
- basis: 12708acf3ae4892d4443627f0d6d5016ddeb29d7; priority: verification; needs: none; scope: `scripts/atlas-board-index.py`, `scripts/atlas_board_items.py`, `scripts/tests/test_atlas_board_index.py`, `scripts/atlas-board-compact.py`, `scripts/tests/test_atlas_board_compact.py`
- Next step: write the failing tests for both tools, then convert `ValueError` into `BoardIndexError` and skip the ladder file by name in the index, and test the ladder heading before the item and narrative classification in compact.
