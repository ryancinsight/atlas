## ATLAS-TEST-TEMPDIR-LEAKS — Atlas Python tests leave temp directories behind [tightening] [patch] — todo
- priority: tightening
- outcome: no Atlas Python test leaves a directory under the OS temp directory after the suite ends, on success or failure.
- evidence: on 2026-10-03 `%TEMP%` held 1,060 `crlf-detector-*`, 158 `atlas-safety-census-repo-*` and 105 `atlas-gate-*` directories, the oldest from 2026-09-10; 1,236 were deleted by hand and 99 recent ones remain. Read at 3ea1f0629: `CrlfStoredBlobsTestCase._repo` (`test_atlas_conformance.py`) registers `shutil.rmtree(root, ignore_errors=True)`, which silently skips the read-only git object files Windows refuses to delete; `MainWalkTestCase._make_repo` (`test_safety_census.py`) calls `mkdtemp` and registers no cleanup. The `atlas-gate-*` leaks are partly traced: the ref-gate tests' `gate.kill()` kills only bash, the hook's children keep `push-1.txt` open, and Windows refuses the delete (fix in draft ryancinsight/atlas#460).
- oracle: every fixture creating a directory removes it on success and failure (`TemporaryDirectory` or `addCleanup`, with an `onexc` handler that clears the read-only bit for git objects, never `ignore_errors`); a test runs the fixture suites against a private temporary root and asserts that root is empty afterward, and a second oracle reads the sources and fails on any fixture that removes its tree with `ignore_errors=True` or never removes it.
- needs: none
- scope: scripts/tests/ (`test_atlas_conformance.py`, `test_safety_census.py`, `test_atlas_pre_push_gate.py`, and any other `mkdtemp` user: `git grep -n mkdtemp -- scripts/tests`)
- next: the `atlas-gate-*` process-tree half lands with #460; the converted fixtures now leave nothing behind, so the fixture side of the sweep is closed.
- Delivered 2026-10-20: the shared read-only-safe removal helper already existed beside the fixtures (`scripts/tests/readonly_tree.py::clear_readonly_tree`), and every `mkdtemp` fixture in `scripts/tests/` now uses it instead of `shutil.rmtree(ignore_errors=True)` or no cleanup at all: `CrlfStoredBlobsTestCase._repo` (`test_atlas_conformance.py`, was `ignore_errors=True`, which swallowed the refusal to delete the fixture's read-only Git objects), `MainWalkTestCase._make_repo` (`test_safety_census.py`, had no cleanup), `ClaimTest.setUp` and `QueueOrderTest.setUp` (`ignore_errors=True`), `SharedTargetDirTestCase.stack` (`test_lockfile_shared_target.py`, whose cleanup was `lambda: None`, so every call left a tree), the symlink fixture in `test_lockfile_check.py` (`ignore_errors=True`), and the pre-push gate's hook root in `test_atlas_pre_push_gate.py`, whose finalizer removed it with `ignore_errors=True`. The oracle is new: `scripts/tests/test_atlas_tempdir_leaks.py` runs those fixture suites against a private temporary root and asserts that root is empty afterward — a private root, so a suite running concurrently on the same host cannot be blamed for a tree it did not create — and a second oracle reads the sources and fails on any fixture that removes its tree with `ignore_errors=True` or never removes it. Neither is vacuous — with one cleanup reverted to `ignore_errors=True` the behavioural oracle fails and names the two leaked `crlf-detector-*` trees, and the source oracle names the reverted fixture, in each of the four forms the six converted fixtures used. 275 tests pass across the eight touched suites, and the seven fixture suites the oracles run report 84 passed and 1 skipped. Measured on this host: 44 `atlas-safety-census-repo-*` trees and the readable `crlf-detector-*` trees were removed by the converted cleanup; 15 `crlf-detector-*` trees remain undeletable — listing, `chmod` and `rmtree` all fail with "Access is denied" on the directory itself — because orphaned `git`/`sh` processes from 2026-10-12, -13 and -16 still hold them, which is the process-tree half this item already assigns to #460.
