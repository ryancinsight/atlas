## ATLAS-KWAVERS-PARAMETER-STRUCTS-20260928 — Collapse the `clippy::too_many_arguments` suppressions into parameter structs [minor] — todo
- priority: tightening
- outcome: kwavers' `allow_sites` fall to the reachable floor, so each call family takes a parameter struct and the suppression deletes rather than re-relaxes. Oracle: `atlas-conformance.py report --repo kwavers` reads `allow_sites` at or below **137**, with no other class raised and the touched crates' suites green per increment.
- scope: `crates/kwavers-{physics,solver,therapy,transducer,driver,diagnostics,gpu,math,medium,simulation,core,analysis}`, and `crates/kwavers-python` only where a site is *not* a `#[pyfunction]` entry point.
- **oracle corrected 2026-09-28, measured:** the original `allow_sites <= 56` is **unreachable**, and the 58 sites it assumed removable are not defects. Of the 254 suppressions present at kwavers' `origin/main` (`1718216a`), **58 sit on `#[pyfunction]` entry points** in `kwavers-python` — the bindings' argument list *is* the public Python API. Collapsing those to a struct would either break every Python caller or require a `**kwargs` adapter, which is the compat shim the standard prohibits. The reachable floor is therefore `316 - (254 - 58) = 62` for the 196 internal sites, and `allow_sites <= 137` is the honest end state if every internal site is converted. The audit's 260 figure is now 254; six have been fixed since.
- distribution (measured): `kwavers-physics` 64 internal, `kwavers-solver` 50, `kwavers-python` 24 internal + 58 pyfunction, `kwavers-therapy` 13, `kwavers-transducer` 10, the rest 1-4 each. Largest single file is `crates/kwavers-python/src/analytical_bindings/cavitation/chirp.rs` (8, all pyfunction); largest internal file is `crates/kwavers-physics/src/analytical/imaging.rs` (6, the six `ivus_*` families).
- state (2026-09-28, measured with the scanner on both trees): `kwavers/allow_sites` is **315** on `origin/main` and **311** on the family branch `refactor/kwavers-imaging-family-rest`. Four of the six `imaging.rs` sites are converted and merged or in flight; `ivus_bmode_image` (13 parameters) is the module's last internal one and is not yet done. The file is **not** closed.
- delivered: `ivus_therapy_pressure_field` (kwavers#867, merged `062d41aaa`) took its own `IvusTherapyPressureFieldInput`. The other four — `ivus_polar_bmode_rf`, `ivus_chapter_metrics`, `ivus_therapy_response`, `ivus_therapy_fields` — are one PR (kwavers#881) because they edit the same module and could not land independently; three earlier single-function PRs were closed as superseded rather than rebased through three conflicting CI cycles.
- the shape the family settled on, which the earlier design note on this item got wrong: **one `*Input<'a>` per function**, matching the `IvusMicrobubbleDeliveryInput` the module already had — *except* for the one real overlap. `ivus_therapy_response` (17) and `ivus_therapy_fields` (21) take the same five tissue masks and the same seven therapy-dose scalars, 14 of their parameters each, so `IvusTissueMasks<'a>` and `IvusTherapyDose` are written once and both use them. `ivus_chapter_metrics` shares two of five masks and deliberately keeps named fields; its doc comment says so, so the split is not re-litigated later.
- two things deliberately not done, both recorded in the PRs: validation did **not** move into constructors, because the tests assert on the exact `Err` strings and that belongs in a pass where every path moves together; and `IvusTherapyDose` does not validate at all, because a shared constructor would have to emit one message for two consumers whose wording differs. The PyO3 `#[pyfunction]` signatures keep their parameters and their suppressions on all three bindings — that is the finding behind the corrected oracle above, not an oversight.
- next: `ivus_bmode_image`, the last internal site in the file, then the next-largest internal family by measurement: `kwavers-solver` 50 sites across `forward/`, `inverse/` and `pstd/`. The `kwavers-python` 24 internal sites come after those, not before — they are the ones where an arity is a Python-adjacent but non-`#[pyfunction]` boundary, and that distinction needs its own look rather than a blanket conversion.
- design (imaging): four shared types, not six bespoke structs — `PolarGrid` (`radius_m`, `theta_rad`, owning the length-match check), `CartesianGrid` (`x_m`, `y_m`), `PolarBMode` (`backscatter`, `attenuation_db_cm_mhz`, `r_axis_m`, `theta_axis_rad`), `TissueMasks` (the five bool masks) — plus per-function scalar structs: `TherapyAcoustics` (`catheter_radius_m`, `frequency_hz`, `duty_cycle`, `sonication_s`) and `ThermalTissue` (`density_kg_m3`, `sound_speed_m_s`, `specific_heat_j_kg_k`) are each shared by two functions, so they are written once. Validation moves into validating constructors and must preserve the existing error strings verbatim, because the tests assert on them.
- classification note: `kwavers-physics` is `publish = true` at `3.0.0` but is **not on crates.io** (crates.io API returns 404 for it; `leto-ops` and `themis-topology` return 200 as controls). So the signature change is a pre-publication API decision, not a semver break, and needs no major bump now. It does mean the surface must be final before `ATLAS-PUB-001` lands — recorded so the publish item inherits a settled API rather than discovering it.
