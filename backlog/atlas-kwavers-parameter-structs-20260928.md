## ATLAS-KWAVERS-PARAMETER-STRUCTS-20260928 — Collapse the `clippy::too_many_arguments` suppressions into parameter structs [minor] — todo
- priority: tightening; scope: `crates/kwavers-{physics,solver,therapy,transducer,driver,diagnostics,gpu,math,medium,simulation,core,analysis}`, and `crates/kwavers-python` only where a site is *not* a `#[pyfunction]` entry point
- outcome: kwavers' `allow_sites` fall to the reachable floor, so each call family takes a parameter struct and the suppression deletes rather than re-relaxes. Oracle: `atlas-conformance.py report --repo kwavers` reads `allow_sites` at or below **137**, with no other class raised and the touched crates' suites green per increment.
- **oracle corrected 2026-09-28, measured:** the original `allow_sites <= 56` is **unreachable**, and the 58 sites it assumed removable are not defects. Of the 254 suppressions present at kwavers' `origin/main` (`1718216a`), **58 sit on `#[pyfunction]` entry points** in `kwavers-python` — the bindings' argument list *is* the public Python API. Collapsing those to a struct would either break every Python caller or require a `**kwargs` adapter, which is the compat shim the standard prohibits. The reachable floor is therefore `316 - (254 - 58) = 62` for the 196 internal sites, and `allow_sites <= 137` is the honest end state if every internal site is converted. The audit's 260 figure is now 254; six have been fixed since.
- delivered: `ivus_therapy_pressure_field` (kwavers#867, merged `062d41aaa`) took its own `IvusTherapyPressureFieldInput`. The other four — `ivus_polar_bmode_rf`, `ivus_chapter_metrics`, `ivus_therapy_response`, `ivus_therapy_fields` — are one PR (kwavers#881) because they edit the same module and could not land independently; three earlier single-function PRs were closed as superseded rather than rebased through three conflicting CI cycles. - the shape the family settled on, which the earlier design note on this item got wrong: **one `*Input<'a>` per function**, matching the `IvusMicrobubbleDeliveryInput` the module already had — *except* for the one real overlap. `ivus_therapy_response` (17) and `ivus_therapy_fields` (21) take the same five tissue masks and the same seven therapy-dose scalars, 14 of their parameters each, so `IvusTissueMasks<'a>` and `IvusTherapyDose` are written once and both use them. `ivus_chapter_metrics` shares two of five masks and deliberately keeps named fields; its doc comment says so, so the split is not re-litigated later.

The `kwavers-python` 24 internal sites come after those, not before — they are the ones where an arity is a Python-adjacent but non-`#[pyfunction]` boundary, and that distinction needs its own look rather than a blanket conversion.
