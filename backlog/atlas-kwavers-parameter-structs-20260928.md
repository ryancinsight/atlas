## ATLAS-KWAVERS-PARAMETER-STRUCTS-20260928 — Collapse the `clippy::too_many_arguments` suppressions into parameter structs [minor] — todo
- priority: tightening
- scope: `crates/kwavers-{physics,solver,therapy,transducer,driver,diagnostics,gpu,math,medium,simulation,core,analysis}`, and `kwavers-python` only where a site is *not* a `#[pyfunction]`.
- outcome: each internal call family takes a parameter struct, so its suppression deletes rather than re-relaxes. Deliveries and their PRs are in the log; this item is the spec and the remaining work.
- **oracle (measured 2026-09-29 at kwavers `6ed0d9344e2`): 245 `too_many_arguments` suppressions, 58 of them on a `#[pyfunction]` entry point and therefore unreachable.** The binding constraint is the **187 internal sites**; the end state is `allow_sites <= 257` (315 total `#[allow(`, minus the 58). The item's original `allow_sites <= 56` and a later `allow_sites <= 137` both mixed that class with this one and are superseded. Per crate: `kwavers-python` 82, `kwavers-physics` 57, `kwavers-solver` 56, `kwavers-therapy` 13, `kwavers-driver` 13, `kwavers-transducer` 8, rest 1-4.
- **the per-site attributes suppress nothing today**: `Cargo.toml:127` sets `too_many_arguments = "allow"` in the workspace lint table, inherited by every member. Verified by stripping all 239 from `kwavers-transducer` and getting zero warnings. The correct end state is `deny` at the workspace with no per-site allows — and deleting the attributes first would land every warning at once, so neither half goes without the other.
- shape: one `*Input<'a>` per function, matching the `IvusMicrobubbleDeliveryInput` the module already had; the one real overlap gets shared types (`IvusTissueMasks` + `IvusTherapyDose`, 14 parameters each, across `ivus_therapy_response` and `ivus_therapy_fields`). A family that shares only part of a set keeps its own struct — `ivus_chapter_metrics` has 2 of 5 masks and says so in its doc comment, as does `leapfrog_step.rs` (4 sites, no shared decomposition at all).
- not done, deliberately: validation stayed in each kernel so the asserted `Err` strings do not move piecemeal; `#[pyfunction]` signatures keep their arity, because a PyO3 entry point's argument list is the public Python API.
- next: `kwavers-physics/analytical/cavitation` (19 sites, the largest area), then `kwavers-solver`'s remaining families, then `kwavers-python`'s 24 internal ones last — those sit on Python-adjacent boundaries that are not `#[pyfunction]` and need their own look.
