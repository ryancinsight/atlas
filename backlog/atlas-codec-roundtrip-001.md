## ATLAS-CODEC-ROUNDTRIP-001 — Codec read/write asymmetry census [arch] [minor] — todo
- **outcome:** every codec the stack advertises can both read and write its format through the unified contract, and the advertised capability matrix is verified against the dispatch function rather than asserted by a test that encodes the current state.
- **verified defect (fix written, not compiled):** `ritk-io` advertised PNG read but hard-returned `"PNG image writing is not implemented on the native substrate"` from `dispatch.rs:277`, and `native_capability_matrix_matches_dispatch` asserted `!is_native_write_capable(ImageFormat::Png)` — the test locked the defect in as intended behavior. Peer commit `feeb56d86` had already added `ritk-png/src/write.rs` (`write_png`, `write_png_volume`, 166 lines plus 185 lines of tests) but never wired it into dispatch, so the writer was unreachable. Fix on lane `feat/ritk-codecs-typed-samples-001`: `native::PngWriter` implementing the same `ImageWriter` contract as `JpegWriter` (no special case in dispatch), `ImageFormat::Png` routed through `crate::ImageWriter::write`, `Png` added to `is_native_write_capable`, and a new `advertised_write_capability_matches_dispatch` that writes through `write_image_native` for every format the matrix advertises — the guard whose absence let the defect survive as a passing test.
- **writer contract correction:** PNG does **not** round-trip bit-exactly. `write_png` normalises `[min, max]` onto 8-bit `[0, 255]` and records nothing, because PNG has no rescale tags. The round-trip test therefore asserts exact shape, exact window endpoints, and order preservation — not value equality, which would fail against a correct implementation.
- **open defects from the same audit, not yet fixed:** TIFF reads RGB (`color.rs:24`, `RgbVolume`) but writes only `Gray32Float` (`writer.rs:64`), so a colour volume cannot round-trip and no test covers it. DICOM's `is_codec_supported()` is defined as `is_compressed()` (`syntax/mod.rs:145-147`), so all 12 encapsulated transfer syntaxes claim support while the multiframe writer honours only 5 and `bail!`s on the rest — the two *lossy* ones (`JpegLsLossy`, `Jpeg2000Lossy`) are the worst, because `ritk-codecs` already has working encoders for both. JPEG-XL is classified encapsulated and supported with no codec in the crate at all. `DeflatedExplicitVrLittleEndian` is recognised then rejected as "not enabled in this lock". `ritk-codecs` claims to be the single source of truth for DICOM pixel primitives but exports no JPEG encoder, which DICOM *does* write. `packbits.rs:4` documents a `packbits_encode` contract naming a function that does not exist, and its proptest covers only the literal-run branch.
- **blocked on ATLAS-OVERLAY-005:** none of this can be compiled. Workspace resolution fails before compilation in the shared tree (`mnemosyne-memory`, then `themis-topology`, then `eunomia`, then `leto`), so `cargo check -p ritk-io --offline` cannot serve as evidence for a codec change. Re-open: land the floor sweep, then compile and run the PNG dispatch wiring.
- **third-party duplication measured:** `kwavers/Cargo.toml` depends on `image`, `jpeg-decoder` and `tiff`; `metis/Cargo.toml` on `png`, `flate2` and `jpeg-encoder`; `helios-simulation` on `image`; nine `ritk` format crates on `image`/`tiff`/`flate2`; `cfd-io` on a second `zstd`. The README assigns raster bytes to `consus-raster` and compression to `consus-compression`, so these are consumers carrying codecs their provider already owns.
